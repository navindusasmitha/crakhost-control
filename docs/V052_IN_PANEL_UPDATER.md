# CrakHost v0.52 — In-Panel Production Updater

v0.52 adds an ADMIN-only **Install update** action to `/deployment`.

## Security model

The Next.js panel does not receive the Docker socket and does not execute arbitrary host commands. A small root-owned systemd service named `crakhost-updater.service` listens only on a Unix socket at:

`/run/crakhost-updater/updater.sock`

The panel receives that socket as a read-only bind mount. Requests are additionally authenticated with `CRAKHOST_DEPLOY_TOKEN`, which is generated by the installer and remains server-side.

The updater agent exposes only:

- `GET /health`
- `GET /status`
- `POST /update`

`POST /update` can only launch `/opt/crakhost/scripts/update-production.sh`. It does not accept a command, path or shell payload from the browser.

## Update flow

1. Verify ADMIN session and same-origin action request.
2. Ask the local updater agent to launch one update job.
3. Create a timestamped `.env` and PostgreSQL backup.
4. Fetch and hard-reset application source to `origin/main`.
5. Build the panel.
6. Run ordered database migrations.
7. Recreate CrakNode so Go source updates are loaded.
8. Restart the panel and commerce cleanup worker.
9. Verify `/api/health` and CrakNode connectivity.
10. Stream the persisted updater log back to the Deployment page.

Concurrent update jobs are rejected.

## Existing VPS bootstrap

An installation that predates v0.52 needs one final terminal bootstrap because the old panel has no privileged updater agent yet. Run the newest updater script directly:

```bash
curl -fsSL https://raw.githubusercontent.com/navindusasmitha/crakhost-control/main/scripts/update-production.sh -o /tmp/crakhost-update.sh
sudo bash /tmp/crakhost-update.sh
```

After v0.52 is running, future normal updates can be started from **Deployment & updates → Install update**.

## Recovery

The SSH fallback remains:

```bash
cd /opt/crakhost
sudo ./scripts/update-production.sh
```

Backups are stored under `/var/backups/crakhost/<UTC timestamp>/`.
