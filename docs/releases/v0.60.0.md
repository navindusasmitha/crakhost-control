# CrakHost Control v0.60.0

## Smart Node Placement

- Provisioning now evaluates every eligible CrakNode instead of taking the first node with the most free RAM.
- The weighted scheduler scores projected CPU, RAM, allocated disk, real backing-disk headroom, host memory pressure and one-minute load.
- Disabled, stale-heartbeat, drained, critically pressured and unsafe-disk nodes remain excluded.
- Explicit node and location constraints are still respected.
- Capacity is rechecked under the existing node advisory lock before the reservation is committed.
- Provisioning preflight returns the selected score and the top eligible ranking for diagnostics.
- Node Administration shows current scheduler readiness and an idle smart score.

## Bounded Auto Recovery

- Servers now have a persisted desired state (`running` or `stopped`) and a per-server auto-recovery switch.
- Manual Start/Restart records a running desired state; Stop/Kill records a stopped desired state, so intentionally stopped servers are not restarted by automation.
- Suspension disables recovery intent until the server is unsuspended.
- Once per minute, the restricted cron worker checks active servers whose desired state is running.
- Exited/created workloads may be started automatically; running but unhealthy/OOM-signalled workloads may be restarted.
- Missing runtimes, dead/removing runtimes and node communication failures are not recreated automatically in this release.
- Recovery is limited to three attempts in ten minutes with a 15-minute cooldown to prevent restart loops.
- Attempts, successes, failures and cooldowns are written to server service events; owners receive recovery/cooldown notifications.
- Existing stopped servers remain stopped during migration. Existing servers already recorded as running keep running intent.

No customer files, databases, backups, billing balances or Docker volumes are deleted by this update.
