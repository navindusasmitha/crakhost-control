# CrakHost Control v0.59.1

## Provisioning reconciliation

- Orders with an attached real server are reconciled to `ACTIVE` when stale lifecycle state says `PENDING`, `PAID`, `PROVISIONING`, or `FAILED`.
- `PROVISIONING` orders without a server for more than 30 minutes become `FAILED` and remain retryable from Admin Orders.
- Unpaid `PENDING` checkout records older than two hours become `CANCELLED` so they do not pollute the live provisioning queue.
- Reconciliation runs through a cron-secret-protected internal endpoint once per minute and when staff open Admin Orders or the admin dashboard.
- The dashboard provisioning queue now contains only paid orders waiting for work and active provisioning jobs.

## Managed PostgreSQL verification

- Managed credentials are used for the login test.
- The test verifies real read/write capability with a temporary table inside a transaction that is rolled back.
- Telemetry includes database size, active connections, connection limit, cache hit ratio, transactions, row writes, temp I/O, deadlocks, stats reset time, and live sessions.
- Passwords remain one-time display values after creation or rotation.

No customer database contents, server files, backups, or billing balances are removed by this update.
